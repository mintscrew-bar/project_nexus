# 제안서: Discord 길드 봇 호스트 권한 범위 (누가 그 서버로 방을 만들 수 있는가)

> 작성일: 2026-07-21
> 상태: 논의 (미착수) — 방향 검토용, 구현 결정 전

---

## 배경

관리자가 Discord 길드 봇 연동을 승인([`approveDiscordGuildLink`](../../apps/api/src/modules/admin/admin.service.ts))하면
해당 서버로 방을 만들 때 음성 채널 자동 생성·결과 임베드 전송을 쓸 수 있다.

문제 제기: **막상 서버에 봇을 추가해도, 서버 주인 본인 말고는 그 서버로 방을 못 만든다.**
반대로 아무나 만들 수 있게 열면 남의 서버에 분탕(채널 도배·임베드 스팸·멤버 이동)이 생길 수 있다.

## 현재 동작 (owner-only)

방 생성 시 다음처럼 검사한다 — [`room.service.ts`](../../apps/api/src/modules/room/room.service.ts) (`createRoom`):

```ts
discordGuildLink.findFirst({
  where: { ownerId: hostId, guildId: dto.discordGuildId, status: "ACTIVE" },
});
```

`ownerId === hostId`. 즉 **봇을 설치하고 승인받은 본인만** 그 서버로 방을 만들 수 있고,
다른 유저에게는 서버 선택지 자체가 노출되지 않는다. 직관과 일치한다.

## 트레이드오프

- **안전(분탕 차단):** 봇 권한이 ManageChannels(음성 채널 자동생성) + MoveMembers(멤버 이동)라,
  아무나 방을 바인딩할 수 있으면 남의 서버에 채널 도배 / 임베드 스팸 / 멤버 끌기가 가능하다.
  owner-only가 이를 원천 차단한다.
- **쓸모(반쪽 기능):** 스트리머·클랜이 "우리 서버에서 내전 돌리자"고 봇을 깔아도
  주인 한 명만 방을 열 수 있다. 주인이 24시간 대기할 수 없으니 커뮤니티 용도로는 기대에 못 미친다.
  → "봇 깔았는데 왜 팀원들은 못 써요?" 문의로 이어질 가능성이 높다.

## 핵심 관점: "열지 말지"가 아니라 "신뢰 단위를 뭘로 잡는가"

| 옵션                              | 쓸모 | 분탕 리스크 | 비고                                                      |
| --------------------------------- | ---- | ----------- | --------------------------------------------------------- |
| 1. 주인만 (현재)                  | 낮음 | 없음        | 안전하지만 기능 반쪽                                      |
| 2. 주인 + 공동호스트 화이트리스트 | 중간 | 낮음        | 주인이 신뢰 유저 지정. 조인테이블+UI 필요                 |
| 3. 클랜 단위                      | 높음 | 낮음~중간   | **스키마에 이미 `DiscordGuildLink.clanId` 존재** (미사용) |
| 4. 길드 멤버 전원                 | 최고 | 높음        | 강한 가드레일 없이는 비추천                               |

- 방 생성 로직은 현재 `clanId`를 전혀 안 쓴다. 클랜 연동 필드가 설계에 반쯤 깔려 있음
  ([schema.prisma `DiscordGuildLink`](../../packages/database/prisma/schema.prisma)).

## 관점 뒤집기: 피해자 = 통제권자

분탕이 나더라도 **봇을 깐 것도, 멤버십을 정하는 것도, 즉시 비활성화
([`disableDiscordGuildLink`](../../apps/api/src/modules/admin/admin.service.ts))도 서버 주인**이다.
게다가 길드마다 수동 승인이라 폭발 반경이 "옵트인한 자기 서버"로 이미 갇혀 있다.
→ Nexus가 과하게 방어할 필요 없이, **신뢰 결정을 주인에게 위임하고 킬스위치를 쥐여주는** 방향이 깔끔하다.

## 결론적 방향

- 신뢰 단위는 개인(주인)도 서버 전체도 아닌 **클랜(옵션 3) 또는 주인 관리형 공동호스트 목록(옵션 2)** 이 적절.
  `clanId` 필드가 이미 있는 걸 보면 원래 의도도 그쪽으로 보인다.
- 무엇을 열든 진짜 리스크는 게이트가 아니라 **봇의 행동**이다. 게이트보다 가드레일이 중요:
  - 길드당 자동생성 채널 수 상한 + 방 종료 시 채널 정리
  - 유저당 방 생성 rate limit
  - 임베드 전송 채널을 주인이 지정한 곳으로 고정(아무 채널 스팸 방지)
