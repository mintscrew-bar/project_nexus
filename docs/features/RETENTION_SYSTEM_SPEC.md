# Nexus 리텐션 시스템 기획서 v0.5

> 상태: 제품·도메인 설계 초안  
> 범위: 출석, 일일·주간·월간 미션, 성장형 업적, Nexus Point, 꾸미기 상점  
> 원칙: 과금과 능력치 보상은 도입하지 않으며, 내전의 정상 참여와 재방문을 강화한다.

## 1. 목표

Nexus의 기존 핵심 루프는 `방 발견 → 참가 → 경기 → 기록`에서 끝난다. 리텐션 시스템은 경기와 다음 경기 사이에 장기 진행감을 만든다.

```text
출석·내전·평가
  → 미션 및 업적 카운트 증가
  → Nexus Point와 업적 단계 획득
  → 상점에서 꾸미기 아이템 구매
  → 프로필·호버 카드·룸·사이트에 장착
  → 다른 사용자에게 노출
  → 다음 미션과 업적을 위해 재참여
```

### 성공 기준

- 첫 내전 완주 사용자의 7일 이내 두 번째 완주율이 증가한다.
- 내전 완주 횟수와 방 정상 종료율이 증가한다.
- 포인트 획득 사용자의 꾸미기 장착률이 증가한다.
- 보상 때문에 탈주, 역할 경쟁, 평가 담합이 증가하지 않는다.

## 2. 설계 원칙

1. **완주가 성과보다 중요하다.** 패배해도 기본 완주 보상은 동일하다.
2. **같은 행동이 모든 주기에 누적된다.** 한 경기 완주가 일일·주간·월간 미션과 업적에 동시에 반영된다.
3. **연속 출석을 강요하지 않는다.** 누적 출석만 사용하고 streak 단절 페널티는 두지 않는다.
4. **보상은 표현형이다.** 팀 밸런스, 랭킹, 방 입장 우선권 등 게임 결과에 영향을 주지 않는다.
5. **포인트 지급은 반드시 재실행 가능해야 한다.** 동일 이벤트 재처리 시 중복 지급하지 않는다.
6. **분석 로그와 보상 원장을 분리한다.** 유실 가능한 `UserEvent` 설계는 포인트 지급의 근거로 사용하지 않는다.
7. **모든 시간 경계는 KST를 사용한다.** 일일은 00:00, 주간은 월요일 00:00, 월간은 매월 1일 00:00에 갱신한다.

## 3. 용어

| 용어                | 의미                                                                                |
| ------------------- | ----------------------------------------------------------------------------------- |
| Nexus Point 또는 NP | 무료로 획득하고 상점에서 사용하는 단일 소프트 재화                                  |
| 보상 대상 경기      | 실제 사용자들이 참여하고 정상 완료된 내전 또는 스크림                               |
| 정상 완주           | 완료된 경기의 참가자 스냅샷에 사용자가 존재하며 보상 제외 조건에 해당하지 않는 상태 |
| 평가                | 완료된 경기 참가자끼리 남기는 `UserRating`                                          |
| 미션 템플릿         | 운영자가 등록한 미션의 조건과 보상 정의                                             |
| 미션 할당           | 특정 기간에 사용자에게 배정된 미션 인스턴스                                         |
| 업적 단계           | 동일 업적의 누적 카운트가 임계치에 도달해 상승한 등급                               |

## 4. 보상 대상과 제외 조건

### 대상

- `COMPLETED` 상태이며 실제 참가자 근거가 남은 경기
- LoL은 `MatchParticipant` 또는 roster snapshot으로 사용자를 식별할 수 있는 경기
- PUBG는 사용자별 참가·결과 연결이 가능한 스크림만 대상
- 동일 경기에 대해 사용자당 한 번만 완주 처리

### 제외

- 봇 사용자 또는 운영 테스트 계정
- 봇만 참가한 방
- 결과 없이 삭제되거나 중단된 방
- 사용자가 참가자 스냅샷에 없는 경기
- 운영자가 보상 제외로 지정한 테스트·리허설 경기
- 데이터 정정으로 무효 처리된 경기

비공개 방은 실제 사용자의 정상 경기라면 기본적으로 포함한다. 어뷰징이 확인되면 방 단위로 보상을 무효화할 수 있어야 한다.

## 5. 활동 이벤트 명세

이 이벤트들은 분석용 클릭 로그가 아니라 미션, 업적, 포인트 계산을 위한 서버 도메인 이벤트다.

| 이벤트 키                    | 발생 조건                             | 멱등성 키                     | 주요 데이터                                | 사용처                  |
| ---------------------------- | ------------------------------------- | ----------------------------- | ------------------------------------------ | ----------------------- |
| `attendance.checked`         | KST 기준 당일 첫 출석 확인            | `userId:dateKst`              | 날짜                                       | 출석, 미션, 포인트      |
| `match.completed`            | 사용자가 보상 대상 경기를 정상 완주   | `userId:matchId`              | 게임, 방, 포지션, 승패, 팀 구성 방식, 인원 | 미션, 업적, 기본 포인트 |
| `match.won`                  | 정상 완주한 경기에서 승리             | `userId:matchId`              | 게임, 팀                                   | 미션, 업적, 승리 보너스 |
| `match.performance_recorded` | 공식 경기 통계 수집 완료              | `userId:matchId:statsVersion` | KDA, 역할, 전투·오브젝트 지표              | 성과 미션·업적          |
| `rating.submitted`           | 완료 경기 참가자에게 유효한 평가 제출 | `ratingId`                    | 경기, 대상                                 | 미션, 업적              |
| `rating.received`            | 다른 참가자에게 유효한 평가 수신      | `ratingId`                    | 경기, 평가자                               | 업적, 소량 포인트       |
| `room.host_completed`        | 방장이 실제 사용자 경기를 정상 종료   | `hostId:roomId`               | 게임, 인원, 예약 여부, 팀 구성 방식        | 미션, 업적              |
| `match.vote_received`        | MVP 또는 ACE 표 획득                  | `voteId`                      | 경기, 투표 종류                            | 업적, 추후 보너스       |
| `mission.completed`          | 할당된 미션의 목표 달성               | `assignmentId`                | 주기, 미션 코드                            | 포인트 지급             |
| `achievement.leveled_up`     | 업적 카운트가 새 임계치 도달          | `userId:achievementCode:tier` | 이전·현재 단계                             | 포인트·배지 지급        |

### 처리 원칙

- 경기 완료, 포인트 원장 생성, 미션·업적 진척 반영은 재처리해도 결과가 같아야 한다.
- 경기 통계가 늦게 수집되면 `match.completed` 이후 `match.performance_recorded`를 별도로 처리한다.
- 이벤트 처리 실패는 재시도 큐로 보낸다. 분석 이벤트처럼 버리지 않는다.
- 포인트 잔액을 직접 증감하지 않고 원장 행을 먼저 만든 뒤 잔액을 계산하거나 트랜잭션 안에서 캐시 잔액을 갱신한다.
- 관리자 조정도 반드시 별도 원장 사유와 메모를 남긴다.

## 6. Nexus Point 경제 v0.2

### 지급표

| 지급 사유      |                         NP | 제한 및 설명                  |
| -------------- | -------------------------: | ----------------------------- |
| 일일 출석      |                          5 | KST 하루 1회                  |
| 경기 정상 완주 |                        100 | 승패와 무관                   |
| 경기 승리      |                         20 | 완주 보상을 받은 경기만       |
| KDA 2.0 이상   |                          5 | LoL, 통계 수집 완료 경기      |
| KDA 3.0 이상   |                         10 | 구간 중 가장 높은 하나만 지급 |
| KDA 5.0 이상   |                         15 | 경기당 성과 보너스 최대 15 NP |
| 유효 평가 수신 |                          3 | 점수와 무관, 하루 최대 15 NP  |
| 일일 미션      |                      20~45 | 난이도별 차등                 |
| 주간 미션      |                    100~220 | 누적 횟수와 조건별 차등       |
| 월간 미션      |                  500~1,200 | 장기 누적 조건                |
| 업적 승급      | 50 / 100 / 200 / 400 / 800 | I~V 단계별 최초 1회           |

KDA는 초기 구현에서 사용하되 역할별 형평성 문제가 확인되면 `match.performance_recorded`의 역할별 기여 점수로 교체한다. PUBG 성과 보너스는 개인 결과 데이터 신뢰성을 확인한 뒤 별도 표를 추가한다.

### 지급 상한

- 경기 완주와 승리 보상에는 일일 상한을 두지 않는다. 실제 경기 수가 비정상적으로 많으면 어뷰징 탐지 대상으로 분리한다.
- KDA 보너스는 경기당 15 NP를 넘지 않는다.
- 평가 수신 보너스는 하루 15 NP를 넘지 않는다.
- 출석만으로 얻는 포인트는 하루 5 NP로 제한한다.
- 관리자 회수는 잔액을 직접 수정하지 않고 음수 원장을 추가한다.

### 주간 예상 획득량

상품 가격의 기준 단위는 꾸준히 활동하는 사용자의 **주간 중앙 획득량**이다. 현재 지급표와 주 5회 경기 사용자를 기준으로 하면 정상 상태의 예상치는 다음과 같다.

| 획득처                |    주간 예상 NP | 산정 기준                                          |
| --------------------- | --------------: | -------------------------------------------------- |
| 경기 완주·승리        |         550~650 | 5회 완주, 승률 약 50%                              |
| 경기 성과·평가        |          40~100 | KDA 보너스와 유효 평가 수신                        |
| 출석                  |           15~35 | 주 3~7일 출석                                      |
| 일일 미션             |         250~400 | 활동일에 배정된 미션 일부 완료                     |
| 주간 미션             |         350~600 | 배정된 4개 중 2~4개 완료                           |
| 월간 미션의 주간 환산 |         400~700 | 월간 보상을 4주로 환산                             |
| **합계**              | **1,600~2,400** | 업적 승급처럼 일회성인 보상은 정상 획득량에서 제외 |

초기 가격 계산에서는 주간 중앙 획득량을 `2,000 NP`로 가정한다. 출시 전 2주간 실제 포인트를 지급하지 않고 예상 지급량만 기록하는 shadow economy를 운영한 뒤, 활성 사용자 P25·P50·P75 획득량에 맞춰 기준값을 보정한다.

### 가격 결정 공식

```text
상품 가격
= 주간 중앙 획득량
× 목표 획득 주수
× 상품 가치 계수
```

| 상품 특성                     | 가치 계수 |
| ----------------------------- | --------: |
| 정적이며 본인에게 주로 노출   |       0.7 |
| 정적이며 다른 사용자에게 노출 |       1.0 |
| 애니메이션이며 본인에게 노출  |       1.3 |
| 애니메이션이며 공개 노출      |       1.7 |
| 시즌·한정성 포함              |  2.0 이상 |

가치 계수는 제작 비용이 아니라 사용자가 체감하는 노출 범위, 모션, 희소성을 반영한다. 예를 들어 주간 중앙 획득량이 2,000 NP이고 목표 기간이 3주인 공개 애니메이션 상품은 `2,000 × 3 × 1.7 ≈ 10,200 NP`이므로 10,000 NP 전후에 배치한다.

### 업적 전용 상품 가격

업적 전용 상품은 달성 조건 자체가 희소성을 만들기 때문에 일반 상품보다 가격을 과도하게 높이지 않는다.

| 예시 상품                     | 구매 조건       | 권장 가격 |
| ----------------------------- | --------------- | --------: |
| 베테랑 III 전용 프로필 프레임 | `A_VETERAN` III |  2,000 NP |
| 방장 IV 전용 프로필 배너      | `A_HOST` IV     |  4,000 NP |
| 베테랑 V 전용 룸 입장 이펙트  | `A_VETERAN` V   |  6,000 NP |

### 초기 카탈로그 총량

출시 상품을 모두 구매하는 데에는 주간 2,000 NP 획득 사용자를 기준으로 최소 4~6개월이 걸려야 한다.

| 구성     |   수량 | 평균 가격 |          합계 |
| -------- | -----: | --------: | ------------: |
| 입문     |      4 |    500 NP |      2,000 NP |
| 일반     |      6 |  1,500 NP |      9,000 NP |
| 고급     |      4 |  4,500 NP |     18,000 NP |
| 희귀     |      3 |  8,000 NP |     24,000 NP |
| **전체** | **17** |           | **53,000 NP** |

포인트 획득량이 설계값보다 높더라도 가격을 즉시 올리지 않는다. 먼저 비정상 반복 경기, 평가 담합, 중복 지급 여부를 확인하고, 정상적인 활동 증가라면 다음 카탈로그의 가격과 출시 속도로 흡수한다.

## 7. 미션 시스템

### 배정 규칙 v0.4

- 일일: 매일 3개 배정, 첫 교체 무료, 이후 NP로 추가 교체
- 주간: 매주 4개 배정, 첫 교체 무료, 이후 NP로 추가 교체
- 월간: 매월 4개 배정, 무료 교체 없이 NP로 교체
- `PASSIVE` 태그는 일반 슬롯을 차지하지 않는 보너스 미션으로 주기별 최대 1개만 활성화
- 완료 즉시 자동 수령한다. 별도의 수령 버튼 때문에 보상을 잃지 않게 한다.
- 한 행동은 여러 주기 미션과 업적을 동시에 진척시킨다.
- 같은 태그의 미션은 한 주기에 중복 배정하지 않는다. 예: `PLAY_COUNT_1`과 `PLAY_COUNT_2` 동시 배정 금지
- 계정에 연결된 게임과 실제 활동 이력에 맞는 미션만 배정한다.
- 방장 경험이 없는 신규 사용자에게 방장 미션을 강제 배정하지 않는다.

### NP 미션 교체

마음에 들지 않는 일반 미션은 같은 주기 안에서 다른 미션으로 교체할 수 있다. 교체 비용은 사용자별·주기별 누적 교체 횟수에 따라 증가하며, 일일·주간 무료 교체도 누적 횟수에 포함한다.

| 주기 | 무료 교체 | 첫 유료 교체 | 두 번째 유료 | 세 번째 유료 | 주기당 최대 교체 |
| ---- | --------: | -----------: | -----------: | -----------: | ---------------: |
| 일일 |       1회 |        15 NP |        30 NP |        60 NP |           총 4회 |
| 주간 |       1회 |        50 NP |       100 NP |       200 NP |           총 4회 |
| 월간 |      없음 |       150 NP |       300 NP |       600 NP |           총 3회 |

비용과 횟수는 일일은 KST 날짜, 주간은 KST 월요일 시작 주차, 월간은 KST 연월이 바뀔 때 초기화한다.

#### 교체 규칙

- 완료되어 보상이 지급된 미션과 `PASSIVE` 보너스 미션은 교체할 수 없다.
- `PASSIVE` 미션이 보기 싫은 경우 비용 없이 숨길 수 있다.
- 새 미션은 기존 미션과 같은 `slotType`, 같은 주기, 같은 난이도 구간에서 선택한다.
- 이미 활성화된 코드, 같은 주기에 버린 코드, 현재 활성 미션과 충돌하는 태그는 후보에서 제외한다.
- 적격 후보가 없으면 교체 버튼을 비활성화하고 NP를 차감하지 않는다.
- 새 미션은 교체 시점부터 진척을 계산한다. 교체 전에 했던 행동을 소급해 즉시 완료할 수 없다.
- 일부 진척된 미션을 교체하면 기존 진척은 복구되지 않는다. 확인 화면에 잃게 되는 진행도를 표시한다.
- 교체 결과를 먼저 보여주거나 결과를 확인한 뒤 취소하는 기능은 제공하지 않는다.
- 잔액 부족, 동시 요청, 서버 오류가 발생하면 미션 교체와 NP 차감을 모두 롤백한다.
- NP 차감 원장은 `mission-reroll:userId:cadence:periodKey:sequence` 멱등성 키를 사용한다.
- 기존 미션의 `REROLLED` 처리, 새 미션 생성, NP 차감 원장 생성은 하나의 DB 트랜잭션으로 처리한다.

#### 교체 경제 원칙

- 유료 교체는 상점 외의 보조적인 NP 소비처이며, 미션 보상보다 확정적인 순이익을 제공해서는 안 된다.
- 쉬운 미션을 뽑기 위한 반복 교체를 막기 위해 난이도 구간을 유지한다.
- 실제 교체 사용률이 일일 활성 사용자의 30%를 넘으면 비용보다 배정 품질과 미션 풀을 먼저 점검한다.
- 교체로 소비되는 NP는 전체 월간 NP 소비량의 5~15%를 목표로 한다. 상점 구매를 방해할 정도라면 비용을 낮춘다.
- 운영 오류나 잘못된 자격 판정으로 불가능한 미션이 배정된 경우 교체 비용을 받지 않고 운영자가 무료 재배정한다.

### 미션 어뷰징 방지

- 평가 제출 미션은 동일 대상 반복이 아니라 서로 다른 경기 기준으로 계산한다.
- 낮은 평가를 받았다는 이유로 미션 진행이나 포인트를 차감하지 않는다.
- 평가 점수에 비례해 포인트를 주지 않는다. 담합 유인을 줄이기 위해 유효한 평가 수신 여부만 본다.
- 승리·KDA 미션은 전체 배정의 절반을 넘지 않는다.
- 포지션 미션은 자동 배정 전에 사용자의 게임과 역할 데이터 지원 여부를 검사한다.
- `PASSIVE` 미션은 완료하지 못해도 일반 미션 완수율이나 연속 완료 기록에 영향을 주지 않는다.
- 킬·KDA 미션과 시야·어시스트 미션을 같은 날 함께 배정하지 않아 특정 역할을 강제하지 않는다.
- 고유 사용자 수 미션은 봇과 무효 경기 참가자를 제외하고 같은 사용자를 한 번만 센다.
- 특정 팀 구성 방식 미션은 사용자가 참여 가능한 공개·예약 방이 없는 날에는 일일 풀에서 제외한다.
- 고유 사용자 목표는 직전 동일 기간의 실제 고유 참가자 수의 60%를 넘지 않게 동적으로 제한한다. 현재 규모에서 달성 불가능하면 해당 미션을 배정하지 않는다.

### 업적 보상

업적의 달성 난이도와 희소성에 따라 네 가지 보상 프로필을 적용한다. 반복 플레이만으로 오르는 누적 업적과 드문 플레이를 요구하는 업적에 같은 보상을 지급하지 않는다.

| 보상 프로필 | 성격                               |   I |  II | III |  IV |     V | 단계 NP 합계 |
| ----------- | ---------------------------------- | --: | --: | --: | --: | ----: | -----------: |
| `GROWTH`    | 자연스럽게 누적되는 장기 기록      |  20 |  40 |  80 | 160 |   320 |       620 NP |
| `MASTERY`   | 특정 역할·활동을 꾸준히 수행       |  30 |  60 | 120 | 240 |   480 |       930 NP |
| `CHALLENGE` | 명확한 성과나 사회적 기여 필요     |  50 | 100 | 200 | 400 |   800 |     1,550 NP |
| `LEGEND`    | 매우 드문 기록 또는 장기 최고 기록 | 100 | 200 | 400 | 800 | 1,600 |     3,100 NP |

50개 업적을 모두 V단계까지 달성했을 때의 이론상 총 업적 보상은 `55,180 NP`다. 대부분 수개월~수년이 필요한 누적 보상이므로 정상 주간 획득량에는 포함하지 않지만, 출시 시 소급 지급량을 계산할 때는 별도로 반영한다.

### 난이도 밸런싱 목표

일반 누적 업적은 활동 사용자 기준으로 다음 기간과 달성률을 목표로 한다. 희귀 사건형 업적은 기간 대신 실제 발생 분포를 사용한다.

| 단계 | 목표 달성 기간     | 해당 단계 이상 달성자 목표 비율 |
| ---- | ------------------ | ------------------------------: |
| I    | 첫 세션 또는 첫 주 |                          60~80% |
| II   | 1~3주              |                          30~50% |
| III  | 1~3개월            |                          10~25% |
| IV   | 3~9개월            |                            2~8% |
| V    | 12개월 이상        |                       1~3% 이하 |

- 단계 간 요구치는 단순 등차가 아니라 대략 `1 → 5~10 → 20~50 → 50~200 → 150~500`의 장기 곡선을 사용한다.
- 누적량이 큰 피해·골드·CS 계열은 운영 데이터의 P50·P75·P90·P97·P99 분위수로 임계치를 다시 산정한다.
- 달성자 비율이 목표보다 2배 이상 높거나 낮으면 신규 사용자에게만 바뀐 임계치를 적용하지 않고, 전체 정의 버전을 올려 일관되게 재계산한다.
- 업적 NP는 정상 상태에서 전체 주간 포인트 공급량의 15%를 넘지 않도록 한다.
- `LEGEND` 업적은 쉬워졌다는 이유로 이미 획득한 단계나 보상을 회수하지 않는다.

### 집계 규칙

- 모든 단계 아이콘은 프로필의 대표 업적 슬롯에 장착 가능
- 기존 전적에서 신뢰성 있게 계산할 수 있는 값은 출시 시 소급 적용
- 출석은 기능 출시일부터만 집계하며 과거 `lastSeenAt`으로 소급하지 않음
- 연승은 무효·취소 경기를 건너뛰고 시간순으로 계산하며, 게임 종류별 연승을 섞지 않음
- 포지션별 업적은 기록된 실제 포지션을 사용하고 역할 선택 화면의 희망 포지션은 사용하지 않음
- MVP와 ACE는 `MatchVote.voteType`을 분리 집계함

### 소급 적용 기준

| 적용 방식                | 업적                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 기존 데이터로 전체 소급  | 완주, 승리, 패배 완주, 평가, 투표, KDA, 포지션, 챔피언, 킬·어시스트·피해량·시야·CS·골드·오브젝트·멀티킬 계열 |
| 데이터 연결 검증 후 소급 | 방장, 예약 방, 만원 방, 팀 구성 방식, 고유 팀원                                                              |
| 출시일부터 집계          | 출석 및 기존 데이터에서 유일성을 보장할 수 없는 항목                                                         |

소급 승급 시 달성한 모든 단계와 장식은 즉시 개방한다. 다만 대량의 포인트가 한 번에 공급될 수 있으므로 shadow economy에서 소급 총액 분포를 별도로 계산한 뒤, `전액 지급`, `출시 보너스 상한 적용`, `기간 분할 지급` 중 하나를 출시 전에 확정한다.

### 업적 설계 가드레일

- 누적 피해량·킬처럼 특정 역할에 유리한 업적은 대표 업적 선택지일 뿐 미션 배정 조건으로 사용하지 않는다.
- 패배 완주 업적은 패배를 유도하는 것이 아니라 결과와 무관한 정상 완주를 인정하기 위한 장치다.
- 오브젝트 처치는 Riot 개인 통계의 의미를 검증한다. 마지막 타격만 기록되는 값이면 팀 단위 기여 업적으로 교체한다.
- KDA, 연승, 멀티킬 업적은 별도 NP 성과 보너스를 추가 지급하지 않는다. 단계 승급 보상만 지급한다.
- 커뮤니티 게시글·댓글·좋아요 수는 반복 파밍과 저품질 활동을 만들 수 있어 초기 업적에서 제외한다.
- 고유 팀원 수 계산 시 봇, 삭제된 사용자, 무효 경기를 제외하고 동일 사용자는 한 번만 센다.

### 상품 원칙

- 상품은 능력치, 랭킹, 밸런스, 방 권한에 영향을 주지 않는다.
- 구매 전 실제 적용 위치에서 미리보기를 제공한다.
- 애니메이션 상품은 `prefers-reduced-motion`과 사용자 효과 끄기 설정을 따른다.
- 사이트 테마는 텍스트 대비와 주요 운영 UI의 가독성 검사를 통과해야 한다.
- 품절이나 확률형 구매는 v0.5 범위에 포함하지 않는다.
- 기간 한정 상품도 구매한 뒤에는 영구 소유한다.
- 구매는 원장 차감과 소유권 생성을 하나의 DB 트랜잭션으로 처리한다.

## 13. 관리자 운영 콘솔

### 관리자 정보 구조

기존 관리자 사이드바의 `콘텐츠` 그룹에 ADMIN 전용 `리텐션 운영` 탭 하나를 추가한다. 상위 탭을 미션·업적·상점별로 늘리지 않고, 탭 내부의 보조 내비게이션으로 나눈다.

```text
리텐션 운영
├─ 현황
├─ 미션
├─ 업적
├─ 상점
├─ 포인트·원장
└─ 이상 활동
```

리텐션 시스템은 공통 계정 경제이므로 관리자 상단의 `공통 / LoL / PUBG` 범위 중 `공통`에서 노출한다. 현황과 정의 목록 안에서는 게임 범위를 별도 필터로 제공한다.

### 권한

| 기능                     | ADMIN | MODERATOR          |
| ------------------------ | ----- | ------------------ |
| 운영 현황·정의 조회      | 전체  | 읽기 전용          |
| 미션·업적·상품 초안 작성 | 가능  | 불가               |
| 예약·활성·일시정지·보관  | 가능  | 불가               |
| 포인트 수동 지급·회수    | 가능  | 불가               |
| 업적 재계산·소급 작업    | 가능  | 불가               |
| 이상 활동 검토           | 가능  | 조회와 메모만 가능 |
| 보상 무효화·원장 정정    | 가능  | 불가               |

초기 구현에서는 `리텐션 운영` 탭 전체를 ADMIN 전용으로 출시한다. MODERATOR 읽기 권한은 운영 인력이 실제로 필요해질 때 열어도 된다.

### 현황 대시보드

#### 핵심 카드

- 오늘·7일·30일 NP 발행량과 소비량
- 미사용 NP 총액, 사용자당 P50·P75·P95 잔액
- 상점 소비와 미션 교체 소비 비율
- 일일·주간·월간 미션 완료율
- 무료·유료 교체율과 평균 교체 비용
- 업적 단계별 승급 수와 소급 지급량
- 상점 구매율, 첫 구매 전환율, 구매 후 장착률
- 보상 대상 경기 수와 중복 지급 차단 건수

#### 차트와 경고

- 일별 NP 발행·소비·순증 추이
- 지급 사유별 공급 비중과 소비처별 소각 비중
- 미션별 배정·교체·완료 퍼널
- 업적별 I~V 달성자 분포
- 상품별 구매·장착·미사용 비율
- P95 잔액이 초기 고급 상품 가격의 5배를 넘으면 인플레이션 경고
- 특정 미션 교체율이 40%를 넘으면 배정 품질 경고
- 동일 지급 멱등성 키 충돌이나 보상 재시도 누적 시 시스템 경고

### 미션 관리

#### 목록

- 주기, 게임 범위, 상태, 슬롯 유형, 난이도, 태그로 필터
- 배정 수, 완료율, 교체율, 평균 완료 시간, 지급 NP 표시
- 교체율·포기율이 높은 미션을 상단 경고로 표시
- 템플릿 복제, 초안 생성, 예약 활성화, 일시정지, 보관 제공

#### 편집

- 이름과 설명
- `DAILY / WEEKLY / MONTHLY` 주기
- 게임 범위와 지원 데이터 조건
- 슬롯 유형, 난이도, 가중치, 충돌 태그
- 조건 이벤트, 목표 값, NP 보상
- 사용자 자격 조건과 동적 목표 제한
- 활성 시작·종료 시각과 KST 기간 미리보기
- 예상 후보 사용자 수와 최근 데이터 기준 예상 완료율

활성 템플릿은 조건·목표·보상을 직접 덮어쓰지 않는다. 수정본을 새 버전의 초안으로 만들고 다음 주기부터 적용한다. 긴급한 오류에는 일시정지를 사용하며 이미 완료된 보상은 자동 회수하지 않는다.

#### 배정 시뮬레이션

- 지정한 사용자 또는 표본 사용자 100명에게 어떤 미션이 배정되는지 dry-run
- 같은 태그 충돌, 후보 부족, 지원하지 않는 게임 통계, 달성 불가능한 목표 검출
- 주기별 예상 총 지급량과 사용자별 P25·P50·P75 표시
- 변경 전후 배정 분포 비교 후에만 게시 가능

### 업적 관리

- 코드, 이름, 게임 범위, 카운터, 보상 프로필, 현재 버전 검색
- I~V 임계치와 예상 달성률, 실제 달성자 분포 비교
- 단계별 칭호·아이콘·프레임·이펙트 미리보기
- 업적 전용 상점 상품 연결 상태 확인
- 단일 사용자 재계산, 전체 backfill 미리보기, 배치 실행과 진행 상태 제공
- 이전 정의와 새 정의의 승급·강등 대상 및 예상 NP 차이를 게시 전에 표시

한 명이라도 진척을 가진 업적 정의는 삭제하지 않는다. `DRAFT / SCHEDULED / ACTIVE / PAUSED / ARCHIVED` 상태와 정의 버전을 사용한다. 임계치가 변경되어도 이미 지급된 단계와 보상을 회수하지 않는 것을 기본값으로 한다.

### 상점 관리

- 상품 코드, 이름, 카테고리, 장착 슬롯, 희귀도, 가격, 상태 관리
- 정적·애니메이션 에셋 업로드와 프로필·호버·룸·사이트 적용 미리보기
- 업적 코드와 최소 단계 구매 조건 연결
- 판매 시작·종료 예약, 표시 순서, 신규·한정 라벨 관리
- 판매량, 구매자 수, 장착률, 구매 후 미장착률 표시
- 특정 상품 직접 지급과 오류 구매 환불

상태는 `DRAFT / SCHEDULED / ACTIVE / PAUSED / ARCHIVED`를 사용한다. 이미 판매된 상품을 보관 처리해도 소유자는 계속 장착할 수 있다. 렌더링 오류나 보안 문제가 있는 상품만 `PAUSED`로 전체 장착을 막고 기본 외형으로 대체한다.

### 포인트·사용자 상세

관리자는 사용자 검색 후 다음 내용을 한 화면에서 확인한다.

- 현재 NP 잔액과 총 획득·소비량
- 시간순 PointLedger와 지급 사유·원본 경기·미션·업적 링크
- 현재 및 과거 미션, 교체 내역과 비용
- 업적 카운트와 단계별 달성 시각
- 구매 상품, 직접 지급 상품, 현재 장착 상태
- 보상 보류·회수·정정 기록

수동 조정은 잔액을 직접 수정하지 않고 `ADMIN_GRANT` 또는 `ADMIN_REVOKE` 원장을 추가한다. 관리자 ID, 필수 사유, 변경 전후 잔액, 관련 사용자·경기·미션을 기록한다. 잔액보다 큰 회수는 기본적으로 차단하고, 부정 획득 회수로 음수 잔액을 허용해야 한다면 별도 확인 절차를 거친다.

### 이상 활동 관리

#### 탐지 조건

- 짧은 시간에 동일 참가자 조합으로 반복 완료된 경기
- 동일 사용자 쌍의 반복 평가와 상호 평가 집중
- 평균 대비 과도한 경기·KDA·평가 포인트 획득
- 동일 멱등성 키 충돌, 비정상 재시도, 관리자 수동 지급 반복
- 미션 교체 직후 비정상적으로 높은 즉시 완료율
- 계정 생성 직후 고가 상품 구매가 가능한 비정상 잔액

#### 처리 흐름

```text
OPEN → REVIEWING → RESOLVED 또는 DISMISSED
```

- 자동 탐지는 포인트를 즉시 회수하거나 계정을 자동 제재하지 않는다.
- 관리자가 경기·평가·원장을 확인한 뒤 지급 보류, 원장 정정, 경기 보상 무효화를 선택한다.
- 원장 정정은 기존 행을 삭제하지 않고 반대 부호의 정정 행을 추가한다.
- 일반 계정 제재가 필요하면 기존 유저 관리·신고 관리 화면으로 연결한다.

### 게시와 변경 안전장치

- 모든 변경은 초안에서 시작하고 `미리보기 → 검증 → 예약 또는 즉시 게시` 순서를 따른다.
- 활성 정의는 삭제하지 않고 일시정지 또는 보관한다.
- 대량 지급, 회수, backfill은 대상 수와 총 NP를 dry-run으로 보여준 뒤 확인 문구를 입력해야 실행된다.
- 배치 작업은 진행률, 성공·실패 수, 재시도 상태를 제공하고 중복 실행을 막는다.
- 미션·업적·상품의 당시 정의 스냅샷을 원장 메타데이터에 남겨 이후 변경에도 과거 내역을 설명할 수 있게 한다.
- 모든 쓰기 작업은 기존 `AdminAuditLog`에 관리자, 액션, 대상, 변경 전후 값, 사유를 기록한다.
