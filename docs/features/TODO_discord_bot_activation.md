# 디스코드 봇 업데이트 — 내전 개최 활성화

작성일: 2026-09-01
목표: **내전 개최 빈도를 0에서 1 이상으로 만든다**

## 왜 이 기획인가 — 실측 진단

2026-09-01 운영 DB 조회 결과다. 추정이 아니다.

| 단계 | 수치 | 판정 |
|---|---|---|
| 가입 유저 | 387명 (최근 30일 +85) | ✅ 획득은 되고 있다 |
| 디스코드 연동 | 387명 (100%) | ✅ |
| 라이엇 연동 | 347명 (90%) | ✅ |
| 봇 연동 길드 | 11개, 전부 ACTIVE | ✅ 유치도 됐다 |
| **방 개설** | **총 4개** | ❌ |
| **정원 충족** | **0건** | ❌ |
| **내전 진행** | **0건** | ❌ |

개설된 방 4개 전부:

```
2026-08-08 | WAITING | 참가 1명 | 길드 X | 테스트
2026-08-12 | WAITING | 참가 2명 | 길드 X | 김경희
2026-08-15 | WAITING | 참가 5명 | 길드 O | 노도식 02시 30분 내전
2026-08-16 | WAITING | 참가 4명 | 길드 O | 내전1235
```

**4개 모두 WAITING에서 죽었다.** 마지막 개설이 8/16, 이후 보름 넘게 0건이다.

### 결론

이건 기능 부족이 아니다. 봇은 이미 슬래시 14개 + 음성 채널 자동화 + 인증 패널까지 갖췄고,
길드 11개가 붙었고, 387명이 연동을 마쳤다. **깔때기의 마지막 한 칸에서 100% 붕괴한다.**

그러므로 이번 업데이트는 **새 기능을 더하는 게 아니라, 이미 만든 것이 사람들 눈에 닿게 하는 것**이다.

## 근본 원인 (코드로 확인함)

### 원인 1 — 외부 서버 10곳은 모집 알림을 못 본다 ⭐ 최대 구멍

`discord-voice.service.ts` `getRoomNotificationTarget()`:

```ts
const isHomeGuild = !room.discordGuildId || room.discordGuildId === homeGuildId;
if (isHomeGuild) {
  // 홈 길드만 중앙 모집 채널(DISCORD_NOTIFICATION_CHANNEL_ID)로 간다
  if (centralChannelId) return { guildId, channelId: centralChannelId };
}
// 외부 길드 → 방 대기실 채널로 폴백
const lobbyChannelId = room.discordChannels?.[0]?.channelId;
```

그런데 그 "대기실"은 `createRoomChannels()`에서 만드는 **음성 채널**이다
(`name: "── 대기실 ──", type: ChannelType.GuildVoice`).

즉 외부 길드에서는 **방을 만든 직후 생성된, 아무도 보고 있지 않은 음성 채널의 텍스트 챗에**
내전 모집 공지가 올라간다. 롤파크·심리전 내전방·내전내전 같은 실제 커뮤니티 10곳의
멤버들은 **내전이 열린 사실 자체를 모른다.**

### 원인 2 — 길드별 공지 채널을 지정할 방법이 없다

`DiscordGuildLink` 스키마에 `announceChannelId` 류 필드가 없다.
중앙 공지 채널은 `DISCORD_NOTIFICATION_CHANNEL_ID` 환경변수 하나뿐이고 홈 길드 전용이다.
서버 관리자가 "우리 서버는 #내전모집 채널로 받겠다"고 정할 수단이 없다.

### 원인 3 — 서버 하나로는 10명을 못 채운다

실측 참가자 수가 1 / 2 / 5 / 4명이다. 5v5는 10명이 있어야 시작된다.
서버 단위 모집으로 정원을 채우는 건 지금 규모에서 **구조적으로 어렵다.**
가장 잘된 방도 절반(5명)에서 멈췄다.

### 원인 4 — 예고 없는 즉석 개설

방을 만드는 순간 모집이 시작된다. 후보는 "그 순간 온라인이면서 그 채널을 보고 있는 사람"뿐이다.
"오늘 밤 10시 내전" 같은 예고가 불가능하다.
실제로 방 이름이 `노도식 02시 30분 내전`인 것은, 사용자가 예약 기능이 없어서
**방 제목에 시간을 적어 우회**하고 있다는 증거다.

### 원인 5 — 길드-클랜 연결 0건

`DiscordGuildLink.clanId`가 11개 전부 `null`이다.
커뮤니티 정체성이 NEXUS 쪽으로 이어지지 않아, 봇은 붙어 있어도 관계가 1회성에 머문다.

## 설계 원칙

1. **첫 성공 1건이 목표다.** "빈도 향상"을 논하기 전에 정원이 찬 내전이 한 번은 돌아야 한다.
2. **새 화면을 만들지 않는다.** 사람들은 이미 디스코드에 있다. 디스코드 안에서 끝나야 한다.
3. **개설자에게 일을 시키지 않는다.** 개설자가 사람을 모으는 게 아니라 봇이 모아준다.
4. 원인 1·2는 사실상 버그다. 기능 추가보다 먼저다.

### Phase 4 — 예고제

원인 4. 사용자가 방 제목으로 우회하고 있는 것을 정식 기능으로 만든다.

- [x] Task 13: 방에 `예정 시각(scheduledAt)` 필드 추가 — 즉시 개설과 예약 개설 분리
      `RoomStatus`에 값을 더하지 않고 `scheduledAt` nullable만 추가했다. 예고 방도
      `WAITING`이라 목록·참가·정원 로직을 손대지 않아도 된다. 알림 중복 발송을 막는
      `scheduledRemind1hAt`/`scheduledRemind10mAt`/`scheduledStartNotifiedAt`을 함께 둔다.
- [x] Task 14: `/nexus schedule <time> <mode>` 슬래시 커맨드
      기획 문구는 `내전예약`이었으나 기존 14개 서브커맨드가 전부 영문 소문자라 맞췄다.
      시각 입력은 컨테이너 TZ와 무관하게 항상 KST로 읽는다
      (`21:00` `9시` `내일 20:30` `9월 3일 21시` `2시간 뒤`).
      날짜·오전/오후를 모두 생략했을 때만 "지금 이후 가장 가까운 해석"으로 읽고,
      날짜를 명시하면 적힌 그대로 쓴다 — 추측이 끼면 예약 시각을 신뢰할 수 없다.
- [x] Task 15: 예정 시각 1시간 전 / 10분 전 공지 채널 리마인드
      `DiscordScheduleService`가 매분 `(status, scheduledAt)` 인덱스로 좁은 시간창만 훑는다.
      기존 공지를 edit하지 않고 새 메시지로 보낸다 — edit는 알림이 가지 않는데,
      리마인드의 목적 자체가 알림이다. 알림 역할 멘션은 "1시간 전 + 아직 자리 있음"일 때만 한다.
      참가자 멘션은 원 서버에서만 한다(사본 서버에는 그 사람이 없어 멘션이 깨진다).
      예약 방의 음성채널은 개설 즉시가 아니라 이 10분 전 시점에 만든다 —
      몇 시간짜리 예약이 쌓이면 빈 채널이 서버 목록을 무너뜨린다.
- [x] Task 16: 참가 신청자에게 시작 시 DM 알림
      디스코드 연동된 참가자에게만 보내고, DM을 막아둔 사람의 실패가 나머지를 막지 않는다.
      봇이 꺼져 있던 사이 30분 넘게 지난 예약은 되살리지 않는다 —
      늦게 도착한 "지금 시작합니다"는 안 보내느니만 못하다.

## 범위 밖 — 그러나 걸림돌

**5v5 10명 정원은 지금 규모에서 콜드스타트에 너무 크다.**
가장 잘된 방도 5명에서 멈췄다. 봇으로 도달 범위를 11배 늘려도 정원을 못 채울 가능성이 있다.

봇 기획의 범위를 넘으므로 여기서 결정하지 않되, Phase 1~2 이후에도 정원 충족이 0이면
소규모 모드(2v2·3v3) 지원 여부를 제품 차원에서 논의해야 한다.
