# 경매 리허설 (관리자 부하 재현)

## 왜

2026-08-11 20인 경매방이 무너진 게 지금까지 유일한 실사용 대형 사고다.
그날 터진 것들(연속 유찰, 늘어지는 진행, 호스트 끊김)은 경매가 **실제로
돌아가는 동안에만** 나타나서, 게임 시작까지만 보던 기존 테스트로는
한 번도 잡히지 않았다.

`load-test/scripts/room-auction.js` 로 하네스를 만들었지만 이 호스트에서는
돌릴 수가 없다 — 운영 postgres 가 호스트에 포트를 열지 않아서 봇 시딩이 막힌다
(`docker port nexus-postgres` → 0건). dev compose 로 뚫는 옛 방법은
운영을 내리므로 금지다 (`dev_compose_kills_prod`).

운영 API 안에서 돌리면 DB 와 JWT 를 이미 들고 있어 이 문제가 통째로 사라진다.

## 설계 결정

- **봇 구동은 두 모드**: `light` 는 이미 있는 서버 자동입찰(`_scheduleBotBids`)을
  그대로 쓰고, `full` 은 서버가 자기 자신에게 socket.io 로 붙어 사람과 같은
  경로를 탄다. 8/11 의 사인은 소켓 계층이라 `full` 이 진짜 재현이다.
- **안전장치 4종**: 실유저 있으면 거부 / 동시 1건 + 자동 정리 /
  환경변수 플래그 / 방 목록에서 숨김
- **결과는 관리자 페이지에서 실시간으로** 본다. 전용 소켓 네임스페이스를
  새로 열지 않고 status 를 1초마다 다시 묻는다 — 리허설은 한 번에 하나만
  돌고 관리자 화면에서만 보므로 소켓을 늘릴 이유가 없다.
