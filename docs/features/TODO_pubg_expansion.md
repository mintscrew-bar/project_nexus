# 배틀그라운드 확장 기획

> 작성일: 2026-09-03
> 목적: 롤 전용으로 만들어진 Nexus에 두 번째 게임(PUBG)을 얹는다.
> 전제: 롤 파이프라인을 깨지 않는다. 배그를 붙이려다 지금 도는 것을 멈추면 실패다.

---

## 왜 이 기획인가 — 진단

### 1. 데이터 수집은 배그가 오히려 쉽다

롤에서 내전 자동 집계를 막고 있던 건 "코드 없는 사설방은 match-v5에 안 잡힌다"였다.
토너먼트 코드가 유일한 경로였고, 그마저 프로덕션 키 승인이 지연돼 stub 모드다.

배그는 이 벽이 없다.

| | 롤 | 배그 |
|---|---|---|
| 커스텀 매치 조회 | 토너먼트 코드 발급분만 | **일반 전적에 그대로 잡힘** (`isCustomMatch: true`) |
| 승인 절차 | 프로덕션 키 승인 필요 | 무료 키로 즉시 |
| 보존 | 캐시하면 영구 | **최근 2주** |
| 레이트 | 앱 전체 100req/2분 | 기본 **10req/분** (상향 신청 가능) |
| 매치 생성 | API 불가 | API 불가 (동일) |

**10req/분으로 충분하다.** 배틀로얄은 매치 1건에 전 팀·전원의 순위와 킬이 다 들어 있어,
20팀 80명짜리 라운드도 `플레이어 전적 조회 1 + 매치 상세 1` = **2콜**이면 끝난다.
롤처럼 인원수만큼 긁을 일이 없다. 라운드 사이 간격(보통 10분 이상)을 감안하면 예산은 남는다.

### 2. 진짜 벽은 경기 포맷이다

| | 롤 | 배그 |
|---|---|---|
| 구조 | 2팀 5v5, 팀 vs 팀 | 16~25팀이 한 매치에 동시 참가 |
| 승부 | 단판/다전제 승패 | 순위 점수 + 킬 점수 합산 |
| 진행 | 대진표(토너먼트) | 여러 라운드 누적 → 포인트 리더보드 |
| 포지션 | 5라인 고정 | 없음 |

`Match`/`MatchSeries`가 `teamAId`/`teamBId` 2팀 고정이라 배틀로얄을 표현할 수 없다.
`bracket`·`role-selection` 모듈은 배그에 개념 자체가 없다.

### 3. 코드에 게임 축이 없다 (실측 2026-09-03)

```
스키마 65개 모델 중 10개가 롤 전용
  RiotAccount, RiotAccountRoleTier, ChampionSeasonStat, ChampionScanState,
  ChampionMastery, ChampionPreference, SummonerSeasonTier, KnownPuuid,
  RiotMatchCache, MatchRosterSnapshot

API  235파일 중 riot 49 / tier 27 / puuid 20 / 라인 19   (~20%)
웹   300파일 중 tier 47 / champion 40 / riot 38 / 라인 34 (~15%)

Room 에 게임 구분 필드 없음
teamCountForRoomSize(n) = Math.floor(n / 5)   ← 하드코딩 (packages/types/src/series-preset.ts:225)
enum Role { TOP JUNGLE MID ADC SUPPORT }      ← 밸런스·경매·역할선택·대진표가 전부 의존
```

## 설계 원칙

1. **롤을 멈추지 않는다.** 게임 축을 넣는 리팩터링은 기능 변화 0으로 끝나야 한다.
2. **대진표를 배그에 우겨넣지 않는다.** 배그는 포인트 리더보드다. 새 모델을 판다.
3. **재사용은 "사람" 쪽에서만.** 계정·클랜·커뮤니티·디스코드·방 로비는 그대로. 게임 진행은 별개.
4. **포인트 규칙은 하드코딩하지 않는다.** 내전마다 룰이 다르다. 프리셋 + 편집 가능한 표.
5. **검증되지 않은 자동 수집은 열지 않는다.** 커스텀 매치 실측 전에는 자동 결과 수집을 보류하되,
   라우팅·계정·프로필·수동 결과 입력 등 선행 구조는 진행한다.

---

## 사이트 구조 — 게임 분리

롤과 배그는 **사이트 안에서 나뉜다.** 한 목록에 섞어 보여주지 않는다.

### URL 정책

| | 경로 | 대상 |
|---|---|---|
| 게임별 | `/lol/*` · `/pubg/*` | 내전, 내전 전적, 랭킹, 가이드, 프로필 |
| 공통 | 프리픽스 없음 | 클랜, 커뮤니티, 스트리머, 설정, 대시보드 |

URL만 봐도 게임 무관인지 드러나고, 같은 클랜 목록이 두 경로로 중복 색인되는 SEO 문제도 없다.
기존 경로(`/tournaments`, `/matches`, `/ranking`, `/guide`)는 `/lol/...` 로 301 리다이렉트한다.
이미 색인·공유된 링크가 있으므로 그냥 옮기면 안 된다.

헤더에 게임 스위처를 둔다. 링크에 게임이 담기므로 공유해도 받는 사람이 같은 화면을 본다.

### 무엇을 나누고 무엇을 공유하는가

**게임별로 나눈다**
- 내전(방 목록)·내전 전적·가이드 — 진행 방식 자체가 다르다
- **랭킹** — 롤은 티어·승률, 배그는 평균 순위·킬. 같은 표에 올릴 수 없다

**공유한다**
- 계정·친구·DM·평판·알림 — 사람은 한 명이다
- **클랜** — 한 클랜이 롤팀과 배그팀을 같이 굴리는 게 자연스럽다.
  게임별로 클랜을 따로 만들게 하면 같은 사람들이 클랜 둘을 관리해야 한다.
  클랜은 하나로 두고 **활동 기록·클랜 랭킹만 게임별**로 집계한다.
- **커뮤니티** — 게시판을 쪼개지 않는다. 실측 PV 550/일 규모에서 반으로 나누면
  양쪽 다 글이 안 올라오는 죽은 게시판이 된다. 게임 태그로 구분하고 목록은 합친다.
- **스트리머** — 사람 기준 목록. 방송하는 게임을 배지로 표시한다.

### 프로필

신원은 공통, 전적은 게임별이다.

```
/profile/:id       보는 사람의 현재 게임 컨텍스트로 리다이렉트
                   (그 사람이 해당 게임 미연동이면 연동된 게임으로 폴백)
/lol/profile/:id   상단 공통 + 롤 전적 (티어·라인·챔피언·내전 기록)
/pubg/profile/:id  상단 공통 + 배그 전적 (평균 순위·킬·스크림 이력)
```

상단(어느 게임에서 보든 동일): 닉네임·아바타·가입일·평판·클랜·연동된 게임 배지

**연동하지 않은 게임의 탭은 표시하지 않는다.** 배그를 안 하는 사람 프로필에
빈 배그 탭이 뜨면 안 된다. 설정(`/settings`)에서는 두 게임 연동을 나란히 둔다.

### 데이터 축

```prisma
enum GameTitle { LOL PUBG }

model Room {
  gameTitle GameTitle @default(LOL)   // 기존 방은 전부 LOL
  ...
}
```

게임별로 달라지는 값을 코드 한 곳에 모은다 (`packages/types/src/games/`):

| 항목 | LOL | PUBG |
|---|---|---|
| 팀 인원 | 5 | 모드별 설정 (킬내기 4인부터, 배틀로얄 최대 100명) |
| 팀 수 | `n / 5` | 모드·팀 크기·방장 설정에 따라 결정 |
| 포지션 | 5라인 | 없음 |
| 팀 편성 | 경매·스네이크·순환·자동밸런스·수동 | 경매·스네이크·순환·자동밸런스·수동 |
| 진행 | 역할선택 → 대진표 | 기존 2팀 경기 또는 라운드 반복 → 포인트 |
| 결과 수집 | 토너먼트 코드 | 커스텀 매치 자동 매칭 |

`riot` 모듈은 그대로 두고, 계정 연동·결과 수집·통계 세 지점만
게임 어댑터 인터페이스 뒤로 보낸다. 롤 어댑터는 기존 코드를 그대로 감싼다.

### 게임 모드와 팀 구성은 분리한다

`게임 모드`는 경기 규칙이고 `팀 구성 방식`은 참가자를 팀에 넣는 방법이다.
PUBG도 기존 팀 구성 방식을 모두 제공한다. 새로운 팀 구성 엔진을 별도로 만들지 않고,
팀 크기·팀 수·게임별 점수 계산만 설정으로 주입한다.

| PUBG 게임 모드 | 경기 구조 | 결과 |
|---|---|---|
| 킬내기 | 2팀, 4대4부터 확장 | 킬 수 또는 승패, 기존 Match/MatchSeries 재사용 가능 |
| 배틀로얄 내전 | 2~25팀, 최대 100명, 여러 라운드 | 순위 점수 + 킬 점수 누적 |
| 자유 매치 | 기존 수동 팀 배정 기반 | 결과 입력·전적 반영 여부를 선택 |

킬내기는 기존 2팀 승패·다전제·결과 보고 흐름을 재사용한다.
배틀로얄 내전만 다팀·다라운드 리더보드가 필요하므로 `Scrim` 계열 모델을 새로 만든다.
`자유 매치`는 별도 경기 엔진이 아니라 기존 `MANUAL_TEAM`을 이용한다.

### PUBG 팀 구성

경매·왕복형 스네이크·순환 픽·오토 밸런스·수동 팀 배정을 모두 유지한다.

- 왕복형 스네이크: `T1 → T2 → T3 → T4 → T4 → T3 → T2 → T1`
- 순환 픽: 기존 구현처럼 라운드 시작 팀을 순환
- 주장 선발: 랜덤·티어 우선·직접 지정·자원자
- 주장 선정과 픽 순서 추첨은 분리한다.
- 현재 스네이크 서비스의 5인 팀 하드코딩은 게임별 `teamSize`로 일반화한다.

PUBG의 `1티어·2티어·3티어`는 공식 PUBG 랭크와 다른 NEXUS 내부 편성 등급이다.
초기에는 운영자 지정 또는 승인 등급으로 시작하고, 이후 공식 랭크·평균 순위·평균 킬·
NEXUS 내전 성적을 이용해 자동 산정한다. PUBG에는 롤처럼 포지션별 점수 대신 전체
`편성 점수`를 둔다.

### PUBG 플랫폼 구분 — Steam / Kakao

PUBG 방 생성 시 플랫폼을 필수로 선택한다. 계정 등록에서 샤드를 묻는 것과 별개로,
이번 경기를 어느 플랫폼에서 진행할지는 방 설정으로 확정해야 한다.

```prisma
enum PubgPlatform {
  STEAM
  KAKAO
}
```

- 사용자는 `스팀 배그(스배)` 또는 `카카오 배그(카배)` 중 하나를 선택한다.
- 방 이름 원본은 보존하고 표시 제목에는 `[스배]` 또는 `[카배]`를 서버가 붙인다.
- 방 목록·로비·결과·Discord 공지·공유 미리보기에서 플랫폼 배지를 유지한다.
- PUBG 방은 플랫폼 없이는 생성할 수 없고, LoL 방에는 플랫폼 필드를 노출하지 않는다.
- 계정의 `lastMatchShard`와 방 플랫폼이 다르면 참가 전에 경고한다. 샤드 미확인 상태는
  허용하되, 불일치를 공식 인증 실패처럼 단정하지 않는다.

### 프로필·호버 프로필·계정 등록

사용자 신원과 게임 계정은 공유하지 않고, 현재 게임 라우트의 데이터만 보여준다.

```text
/lol/profile  → Riot 계정·LoL 랭크·라인·챔피언·LoL 내전 전적
/pubg/profile → PUBG 계정·공식 랭크·NEXUS 편성 등급·평균 순위·킬
```

- `/lol/...`에서 PUBG 정보를 표시하지 않는다.
- `/pubg/...`에서 Riot 티어·라인·챔피언을 표시하지 않는다.
- 호버 프로필과 로비 프로필 모달도 현재 `game` 컨텍스트를 그대로 전달한다.
- 공통 페이지(`/settings`, `/dashboard`)의 계정 추가는 게임 선택 후 해당 모달을 연다.
- LoL 등록은 기존 Riot ID·티어·라인·챔피언 흐름을 유지한다.
- PUBG 등록은 닉네임 조회 → Steam/Kakao 조회 → account ID 확인 → 등록 흐름으로 분리한다.
- PUBG API는 소유권을 직접 인증하지 않으므로 등록 화면에서 이를 명시한다.

공통 프로필에는 사용자명·아바타·클랜·평판·가입일·연결 게임만 둔다.
공식 PUBG 랭크와 NEXUS 편성 등급은 서로 다른 카드와 라벨로 표시한다.

## 배그 스크림 포맷

### 진행 흐름

```
방 생성 (배그, 모드·팀 크기·팀 수·스팀/카카오 선택)
  → 팀 편성 (경매 / 스네이크 / 순환 / 오토 밸런스 / 수동)
  → 라운드 1 시작
       호스트가 인게임에서 커스텀 매치 개설·진행
       Nexus 가 참가자 1명의 전적을 폴링 → isCustomMatch + 시작시각으로 해당 매치 식별
       매치 상세 1콜로 전 팀 순위·킬 수집 → 포인트 환산
  → 라운드 2, 3 … 반복
  → 누적 리더보드 확정
```

핵심은 **라운드 결과 자동 매칭**이다. 호스트가 매치 ID를 옮겨 적을 필요가 없어야 한다.
라운드 시작 시각 이후 + `isCustomMatch: true` + 참가자 명단 일치, 세 조건으로 특정한다.

### 새 모델

`Match`/`MatchSeries`는 2팀 고정이라 재사용하지 않는다.

단, 킬내기는 기존 2팀 승패·다전제 구조를 재사용할 수 있다. 다팀 배틀로얄 내전에서만
아래 모델을 사용한다.

```prisma
model Scrim            { roomId, totalRounds, pointRule, status }
model ScrimRound       { scrimId, roundNumber, pubgMatchId?, startedAt, status }
model ScrimTeamResult  { roundId, teamId, placement, kills, points }
```

방에는 PUBG 전용 경기 모드와 플랫폼도 함께 저장한다.

```prisma
enum PubgGameMode { KILL_MATCH BATTLE_ROYALE FREE_MATCH }
enum PubgPlatform { STEAM KAKAO }
```

`Room`의 `pubgPlatform`은 PUBG 방에서 필수이고, LoL 방에서는 null이다.

### 포인트 규칙

순위별 포인트 배열 + 킬당 포인트. 기본 프리셋 하나를 넣고 방마다 편집 가능하게 둔다.
(대회마다 표가 달라 "표준"을 코드에 못 박으면 매번 안 맞는다.)

## 재사용 / 신규 / 폐기

**그대로 재사용** — 계정·인증, 클랜, 커뮤니티, DM·친구·평판, 디스코드 봇(모집 공지·예약·음성채널),
방 로비·채팅, 관리자, 경매·스네이크·순환 픽·수동 팀 배정, 2팀 경기·다전제 결과 흐름

      남은 가치는 유지보수성뿐이라 위험 대비 이득이 큰 곳만 뺐다 —
      게임별로 갈리는 **스테이지 경로 판단**을 `@nexus/types/lobby-stage-path` 로 옮기고
      테스트 11개를 붙였다(웹 앱에는 jest 설정이 없어 API 스위트에서 돈다).
      "배그는 역할 선택을 건너뛴다", "배틀로얄은 대진표가 아니라 스크림으로" 같은
      판단이 1,400줄짜리 화면 파일 안에 묻혀 있어 테스트도 못 붙이던 부분이다.
      소켓·상태 배선 분할은 회귀 위험이 크고 지금 얻을 게 없어 남겨둔다.

### Phase 6 — 결과 노출

- [x] Task 40: 배틀로얄 리더보드 화면 (라운드별 + 누적) (2026-09-04)
      `/[game]/tournaments/:id/scrim`. 팀이 많으면 표가 화면을 넘어 표만 가로 스크롤한다.
      배틀로얄 방은 팀 편성이 끝나면 대진표가 아니라 이 화면으로 간다.
- [x] Task 41: PUBG 전적 — 스크림·킬내기 참가 이력·평균 순위·킬 (2026-09-04)
      `/pubg/matches` 를 열었다(Task 51 의 준비 중 목록에서 뺐다).
      **롤과 화면 축이 다르다** — 롤은 소환사 검색이 중심인데 배그는 PUBG API 로
      남의 내전 기록을 찾아올 방법이 없어 검색 축 자체가 없다. 본인 기록만 보여준다.
      그래서 색인도 막았다(로그인 안 한 크롤러에겐 빈 페이지다).
      요약은 승률이 아니라 평균 순위·라운드당 킬 — 배틀로얄에서 승률은 의미가 약하다.
      판수가 적으면 평균이 흔들리므로 판수를 같이 적는다.
      `/pubg/matches/summoner/*`·`/user/*` 는 롤 전용 개념이라 404 로 끊는다.
- [x] Task 42: Discord 모집 공지·결과 공지를 PUBG 포맷으로 (2026-09-04)
      모집 공지 제목에 플랫폼 태그(Task 25). 결과 공지는 원래 **롤에도 없던 기능**이라
      `sendRoomResultNotification` 을 새로 만들어 기존 공지 채널 파이프라인에 얹었다.
      스크림 확정 → 누적 리더보드, 킬내기 보고 → 승자·킬 수.
      공지 실패가 확정·보고를 막지 않게 비동기로 띄운다.

### Phase 7 — 편성 점수 고도화

- [x] Task 43: 편성 점수 산식 확정 (2026-09-04)
      공식 랭크 40% · 내전 평균 순위 40% · 라운드당 킬 20%.
      **가중치는 근거가 있는 항목끼리만 나눈다** — 없는 항목을 0으로 치면
      공식 랭크만 있는 사람이 조용히 낮게 깔린다.
      순위는 팀 수를 감안해 상위 비율로 환산한다(4팀 중 2위 ≠ 16팀 중 2위).
      킬은 라운드당 8킬에서 상한을 둔다 — 한 판에 몰린 킬로 과대평가되지 않게.
      6라운드 미만이면 내전 성적을 아예 빼고 계산한다.
- [x] Task 44: 자동 산정 · 운영자 보정 · 등급 이력 (2026-09-04)
      `recomputeBalanceScore` 는 본인 입력(SELF)·운영자 보정(ADMIN)을 덮지 않는다.
      사람이 판단한 값을 기계가 조용히 지우면 왜 바뀌었는지 아무도 모른다.
      `PubgTierHistory` 로 변경 이력을 남긴다 — 등급이 **실제로 바뀐 경우에만** 쌓는다
      (재계산마다 같은 값을 남기면 정작 언제 바뀌었는지가 묻힌다).
      운영자 보정에는 사유와 보정자를 함께 기록한다.
- [x] Task 45: 점수 버전·표본 수·산정 시각 표시 (2026-09-04)
      프로필 등급 배지 아래에 "자동 산정 · 12라운드 기준 · 9/4 산정 · v1" 한 줄.
      숫자만 두면 어디서 나온 값인지, 얼마나 믿을 만한지 알 수 없다.
