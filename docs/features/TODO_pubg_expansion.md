# 배틀그라운드 확장 기획

> 작성일: 2026-09-03
> 목적: 롤 전용으로 만들어진 Nexus에 두 번째 게임(PUBG)을 얹는다.
> 전제: 롤 파이프라인을 깨지 않는다. 배그를 붙이려다 지금 도는 것을 멈추면 실패다.

---

## 왜 이 기획인가 — 진단

### 1. 데이터 수집은 배그가 오히려 쉽다

롤에서 내전 자동 집계를 막고 있던 건 "코드 없는 사설방은 match-v5에 안 잡힌다"였다.
토너먼트 코드가 유일한 경로였고, 그마저 프로덕션 키 승인이 지연돼 stub 모드다.

배그는 이 벽이 없다.

| | 롤 | 배그 |
|---|---|---|
| 커스텀 매치 조회 | 토너먼트 코드 발급분만 | **일반 전적에 그대로 잡힘** (`isCustomMatch: true`) |
| 승인 절차 | 프로덕션 키 승인 필요 | 무료 키로 즉시 |
| 보존 | 캐시하면 영구 | **최근 2주** |
| 레이트 | 앱 전체 100req/2분 | 기본 **10req/분** (상향 신청 가능) |
| 매치 생성 | API 불가 | API 불가 (동일) |

**10req/분으로 충분하다.** 배틀로얄은 매치 1건에 전 팀·전원의 순위와 킬이 다 들어 있어,
20팀 80명짜리 라운드도 `플레이어 전적 조회 1 + 매치 상세 1` = **2콜**이면 끝난다.
롤처럼 인원수만큼 긁을 일이 없다. 라운드 사이 간격(보통 10분 이상)을 감안하면 예산은 남는다.

### 2. 진짜 벽은 경기 포맷이다

| | 롤 | 배그 |
|---|---|---|
| 구조 | 2팀 5v5, 팀 vs 팀 | 16~25팀이 한 매치에 동시 참가 |
| 승부 | 단판/다전제 승패 | 순위 점수 + 킬 점수 합산 |
| 진행 | 대진표(토너먼트) | 여러 라운드 누적 → 포인트 리더보드 |
| 포지션 | 5라인 고정 | 없음 |

`Match`/`MatchSeries`가 `teamAId`/`teamBId` 2팀 고정이라 배틀로얄을 표현할 수 없다.
`bracket`·`role-selection` 모듈은 배그에 개념 자체가 없다.

### 3. 코드에 게임 축이 없다 (실측 2026-09-03)

```
스키마 65개 모델 중 10개가 롤 전용
  RiotAccount, RiotAccountRoleTier, ChampionSeasonStat, ChampionScanState,
  ChampionMastery, ChampionPreference, SummonerSeasonTier, KnownPuuid,
  RiotMatchCache, MatchRosterSnapshot

API  235파일 중 riot 49 / tier 27 / puuid 20 / 라인 19   (~20%)
웹   300파일 중 tier 47 / champion 40 / riot 38 / 라인 34 (~15%)

Room 에 게임 구분 필드 없음
teamCountForRoomSize(n) = Math.floor(n / 5)   ← 하드코딩 (packages/types/src/series-preset.ts:225)
enum Role { TOP JUNGLE MID ADC SUPPORT }      ← 밸런스·경매·역할선택·대진표가 전부 의존
```

## 설계 원칙

1. **롤을 멈추지 않는다.** 게임 축을 넣는 리팩터링은 기능 변화 0으로 끝나야 한다.
2. **대진표를 배그에 우겨넣지 않는다.** 배그는 포인트 리더보드다. 새 모델을 판다.
3. **재사용은 "사람" 쪽에서만.** 계정·클랜·커뮤니티·디스코드·방 로비는 그대로. 게임 진행은 별개.
4. **포인트 규칙은 하드코딩하지 않는다.** 내전마다 룰이 다르다. 프리셋 + 편집 가능한 표.
5. **타당성부터 확인한다.** 커스텀 매치 1건을 실제로 수집해 보기 전에는 아무것도 만들지 않는다.

## 사이트 구조 — 게임 분리

롤과 배그는 **사이트 안에서 나뉜다.** 한 목록에 섞어 보여주지 않는다.

### URL 정책

| | 경로 | 대상 |
|---|---|---|
| 게임별 | `/lol/*` · `/pubg/*` | 내전, 내전 전적, 랭킹, 가이드, 프로필 |
| 공통 | 프리픽스 없음 | 클랜, 커뮤니티, 스트리머, 설정, 대시보드 |

URL만 봐도 게임 무관인지 드러나고, 같은 클랜 목록이 두 경로로 중복 색인되는 SEO 문제도 없다.
기존 경로(`/tournaments`, `/matches`, `/ranking`, `/guide`)는 `/lol/...` 로 301 리다이렉트한다.
이미 색인·공유된 링크가 있으므로 그냥 옮기면 안 된다.

헤더에 게임 스위처를 둔다. 링크에 게임이 담기므로 공유해도 받는 사람이 같은 화면을 본다.

### 무엇을 나누고 무엇을 공유하는가

**게임별로 나눈다**
- 내전(방 목록)·내전 전적·가이드 — 진행 방식 자체가 다르다
- **랭킹** — 롤은 티어·승률, 배그는 평균 순위·킬. 같은 표에 올릴 수 없다

**공유한다**
- 계정·친구·DM·평판·알림 — 사람은 한 명이다
- **클랜** — 한 클랜이 롤팀과 배그팀을 같이 굴리는 게 자연스럽다.
  게임별로 클랜을 따로 만들게 하면 같은 사람들이 클랜 둘을 관리해야 한다.
  클랜은 하나로 두고 **활동 기록·클랜 랭킹만 게임별**로 집계한다.
- **커뮤니티** — 게시판을 쪼개지 않는다. 실측 PV 550/일 규모에서 반으로 나누면
  양쪽 다 글이 안 올라오는 죽은 게시판이 된다. 게임 태그로 구분하고 목록은 합친다.
- **스트리머** — 사람 기준 목록. 방송하는 게임을 배지로 표시한다.

### 프로필

신원은 공통, 전적은 게임별이다.

```
/profile/:id       보는 사람의 현재 게임 컨텍스트로 리다이렉트
                   (그 사람이 해당 게임 미연동이면 연동된 게임으로 폴백)
/lol/profile/:id   상단 공통 + 롤 전적 (티어·라인·챔피언·내전 기록)
/pubg/profile/:id  상단 공통 + 배그 전적 (평균 순위·킬·스크림 이력)
```

상단(어느 게임에서 보든 동일): 닉네임·아바타·가입일·평판·클랜·연동된 게임 배지

**연동하지 않은 게임의 탭은 표시하지 않는다.** 배그를 안 하는 사람 프로필에
빈 배그 탭이 뜨면 안 된다. 설정(`/settings`)에서는 두 게임 연동을 나란히 둔다.

### 데이터 축

```prisma
enum GameTitle { LOL PUBG }

model Room {
  gameTitle GameTitle @default(LOL)   // 기존 방은 전부 LOL
  ...
}
```

게임별로 달라지는 값을 코드 한 곳에 모은다 (`packages/types/src/games/`):

| 항목 | LOL | PUBG |
|---|---|---|
| 팀 인원 | 5 | 4 (스쿼드) |
| 팀 수 | `n / 5` | `n / 4` |
| 포지션 | 5라인 | 없음 |
| 팀 편성 | 경매·스네이크·자동밸런스·자유 | 경매·스네이크·자유 (자동밸런스는 라인 점수 기반이라 제외) |
| 진행 | 역할선택 → 대진표 | 라운드 반복 → 포인트 |
| 결과 수집 | 토너먼트 코드 | 커스텀 매치 자동 매칭 |

`riot` 모듈은 그대로 두고, 계정 연동·결과 수집·통계 세 지점만
게임 어댑터 인터페이스 뒤로 보낸다. 롤 어댑터는 기존 코드를 그대로 감싼다.

## 배그 스크림 포맷

### 진행 흐름

```
방 생성 (배그, 정원 = 팀수 × 4)
  → 팀 편성 (경매 / 스네이크 / 자유)
  → 라운드 1 시작
       호스트가 인게임에서 커스텀 매치 개설·진행
       Nexus 가 참가자 1명의 전적을 폴링 → isCustomMatch + 시작시각으로 해당 매치 식별
       매치 상세 1콜로 전 팀 순위·킬 수집 → 포인트 환산
  → 라운드 2, 3 … 반복
  → 누적 리더보드 확정
```

핵심은 **라운드 결과 자동 매칭**이다. 호스트가 매치 ID를 옮겨 적을 필요가 없어야 한다.
라운드 시작 시각 이후 + `isCustomMatch: true` + 참가자 명단 일치, 세 조건으로 특정한다.

### 새 모델

`Match`/`MatchSeries`는 2팀 고정이라 재사용하지 않는다.

```prisma
model Scrim            { roomId, totalRounds, pointRule, status }
model ScrimRound       { scrimId, roundNumber, pubgMatchId?, startedAt, status }
model ScrimTeamResult  { roundId, teamId, placement, kills, points }
```

### 포인트 규칙

순위별 포인트 배열 + 킬당 포인트. 기본 프리셋 하나를 넣고 방마다 편집 가능하게 둔다.
(대회마다 표가 달라 "표준"을 코드에 못 박으면 매번 안 맞는다.)

**그대로 재사용** — 계정·인증, 클랜, 커뮤니티, DM·친구·평판, 디스코드 봇(모집 공지·예약·음성채널),

## 리스크 / 미결

- **콜드스타트가 두 배가 된다.** 롤 내전조차 아직 정원 충족 0회다
  ([TODO_discord_bot_activation.md](./TODO_discord_bot_activation.md) 측정표).
  배그 쪽 커뮤니티를 실제로 데려올 수 있는지가 기술보다 앞선 조건이다.
- **계정 소유권 검증이 약하다.** 롤은 Riot 인증이 있지만 배그는 없다. Task 17이 이 기획에서
  가장 불확실한 항목이고, 사칭을 완전히 막을 방법은 없을 수 있다.
- **2주 보존.** 라운드가 끝나고 방치되면 결과를 영영 못 받는다. 수동 입력 경로(Task 23)가 보험이다.
- **커스텀 매치 개설 권한**(Task 5)이 제한적이라면 롤 토너먼트 코드와 같은 병목이 된다.
  Phase 0에서 가장 먼저 확인해야 한다.
- 샤드 문제는 해소됐다(Task 1). steam·kakao 양쪽 모두 실측으로 확인했다.
- 엔드포인트 경로·응답 스키마는 2026-09-03 실측으로 확인됐다 (Task 2).
