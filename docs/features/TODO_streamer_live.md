## 한 줄 정의

NEXUS에 채널을 등록·인증한 스트리머가 방송을 켜면, **스트리머 탭 상단과 내전 방 목록에 LIVE 표시가 뜨는** 기능. 방송 중인 스트리머가 지금 어떤 내전 방을 열어뒀는지까지 연결해서, 치지직/숲에서는 볼 수 없는 정보를 만든다.

## 설계 전제 (조사 결과)

플랫폼 API를 실제로 호출해 확인한 사실들이다.

| 필요한 것 | 치지직 | 숲(SOOP) |
|---|---|---|
| 채널 기본 정보 | ✅ 공식 API (`/open/v1/channels`, 20개 배치) | ✅ 비공식 방송국 API |
| **방송 중 여부** | ❌ 공식 경로 없음 → 비공식 | ❌ 공식 경로 없음 → 비공식 |
| **라이브 썸네일** | ❌ 공식 경로 없음 → 비공식 | ❌ 공식 경로 없음 → 비공식 |
| 소유권 검증용 필드 | `channelDescription` (채널 소개) | `station_title` (방송국 제목) |

- 치지직 공식 Live API는 **전체 라이브 목록 20개씩 페이징**만 제공한다. 특정 채널을 콕 집어 물을 수 없어 중소 스트리머 판정에 못 쓴다.
- 숲 오픈 API는 제휴 심사(10영업일) 후 키가 나오지만, 우리가 필요한 채널별 방송 상태를 주지 않는다. **그래서 신청하지 않았다.**
- 결론: 라이브 여부·썸네일만 비공식 엔드포인트를 쓰고, `providers/` 한 곳에 격리했다.

## 결정 사항

- **검증된 채널만 노출.** 라이브 뱃지가 붙는 순간 채널 URL 사칭이 실익을 갖기 때문에, 미인증 채널은 스트리머 탭과 LIVE 뱃지 대상에서 제외한다.
- **임베드 플레이어는 만들지 않는다.** 이 기능의 목적이 스트리머 홍보인데, NEXUS에서 시청하게 하면 플랫폼 시청자 수에 안 잡히고 광고도 안 돌아 스트리머에게 손해다. 썸네일 미리보기 + 클릭 시 플랫폼으로 이동.
- **방 목록 LIVE 뱃지는 전면 노출.** 스나이핑 우려가 있지만 유입 효과를 우선한다. 문제가 생기면 그때 호스트 토글을 붙인다.
- **라이브 상태는 Redis에만.** 1분 폴링이 매번 DB를 쓰지 않도록 실시간 상태는 캐시(TTL 90초)에 두고, DB에는 "3일 전 방송" 표시용 `lastLiveAt`만 남긴다.
- **YOUTUBE는 1차 제외.** Data API 쿼터 비용(`search.list` 100 units)이 커서 뒤로 미룬다.
- **탭은 라이브 전용 목록이 아니다.** 등록 스트리머가 적은 초기에 페이지가 비어 보이지 않도록, 전체 스트리머 목록에 방송 중인 사람이 위로 올라오는 형태로 만든다.

## 운영 메모

- 플랫폼 표기는 UI 전체에서 **"SOOP"** 으로 통일한다. 예전에 설정·프로필만 "SOOP", 나머지 컴포넌트는 "숲"으로 갈려 있어서 같은 플랫폼을 못 찾는 문제가 있었다.
- SOOP 코드 대조 대상은 `station_title` + `station_name`을 합친 문자열이라 **둘 중 아무 데나** 코드를 넣어도 통과한다. 방송국 API는 오프라인이어도 응답하므로 방송을 켜지 않고 인증할 수 있다.
- 비공식 엔드포인트가 막히면 `apps/api/src/modules/streamer/providers/` 의 해당 파일만 교체하면 된다. 조회 실패는 전부 `null`로 흡수되어 **LIVE 뱃지만 사라지고 스트리머 탭·목록은 그대로 동작한다.**
- 치지직 OAuth용 환경변수는 `CHZZK_CLIENT_ID` / `CHZZK_CLIENT_SECRET` / `CHZZK_CALLBACK_URL`. GitHub Secrets와 배포 워크플로를 통해 `.env.production`으로 내려준다. 앱 권한은 공식 `/users/me` 호출에 필요한 **"유저 정보 조회"만 요청한다** (스트림키·방송 설정 권한은 요청하지 않음).
- 스키마 변경분(`StreamerFollow` 포함)은 아직 운영 DB에 반영되지 않았다. `migrate deploy` 필요.
