# 배그 내전 진행 방식

## 킬내기

- 8·12·16명, 한 팀은 항상 4명이다.
- 생성/설정에서 10~360분을 지정한다. 모든 팀을 채우고 스크림 시작을 누르면 시간 측정을 시작한다.
- 시작 시 대표 계정 ID·플랫폼·팀 정보를 보관하고 기존 경기 목록을 제외한다. 참가자 전원의 플랫폼 확인과 자동 수집 연결이 필요하다.
- 서버가 스쿼드마다 한 계정의 기록을 반복 조회한다. 저장된 네 계정이 모두 같은 스쿼드로 참여한 경기만 집계하며, 커스텀과 일반 스쿼드 경기를 지원한다.
- 포함 범위는 `startsAt <= PUBG 경기 createdAt < cutoffAt`이다. 종료 후 완료된 경기와 늦게 도착한 API 결과도 수집한다.
- 경기 ID 유니크 제약, Redis 락, 저장된 조회 대기열로 중복 기록과 재시작 시 유실을 방지한다.
- 기본 점수는 킬 +1, 데스 -3, 치킨 +8. 합계가 음수일 수도 있다.
- PUBG 결과 API만으로 아직 진행 중인 마지막 경기의 존재를 확정할 수 없으므로 시간 종료 후에도 수집을 계속한다. 방장이 마지막 경기 반영을 확인하고 확정하면 수집을 종료한다.
- API 지연은 상태 문구로 표시하고 재시도한다. 실시간 인게임 킬 수가 아니라 완료 경기 기록의 자동 집계다.

## 배틀로얄

- 정해진 팀 전원이 정해진 경기 수만큼 플레이한다. 100명/3판은 25개 4인 스쿼드가 3판 모두 참가하며 탈락·승자 진출이 없다.
- 생성/설정에서 1~20판을 지정한다. 각 경기 시작 후 기존 결과 수집 버튼 또는 수동 입력으로 전 팀의 결과를 기록한다.
- 전 팀의 결과가 있어야 해당 경기를 저장하며, 예정된 모든 경기가 끝나야 최종 확정할 수 있다.
- 기본 점수표는 킬당 1점, 1~8위 순서대로 10·6·5·4·3·2·1·1점, 9위 이하는 0점이다. 데스는 통계로 기록한다.
- 기본 동점 비교는 누적 순위 점수 → 마지막 경기 점수 → 마지막 경기 순위 → 마지막 경기 데미지다.
- 근거: [PUBG SUPER v5.0.5, 10장](https://wstatic-prod.pubgesports.com/web/live/static/download/UPDATED-SUPERv5.0.5.pdf). 공식 16팀 규칙의 점수표를 25팀 내전에 확장하며, 17~25위에도 순위 점수 0점을 적용한다.

## 배포 시

`20260908_timed_kill_match` 마이그레이션과 Prisma Client 재생성이 필요하다. 이 변경은 코드 커밋만 수행하며 운영 DB에 자동 적용하지 않는다. 기존 진행 중인 스크림에는 시간 경계를 소급 부여하지 않는다.
