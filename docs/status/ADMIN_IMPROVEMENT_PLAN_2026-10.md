# 관리자 개선안 (2026-10-06)

관리자 화면을 게임 탭(공통/롤/배그) 구조로 바꾼 뒤 남은 개선 항목이다.
운영 안전, 분석, 구조 정리 세 축으로 나눴다. **한 Phase 가 끝나면 커밋·검증하고 다음으로 간다.**

## 전제와 제약

- 이미 한 것: 게임 탭 구조, 커뮤니티·스트리머 게임 범위, 게임별 대시보드, 배그 스크림 상세·조치, 롤 수집 재시도 (커밋 `c3f29936` ~ `0702f8f7`, 미푸시)
- 확인된 사실: `adminAuditLog` 는 기록만 있고 조회 API·화면이 없다. `User.lastSeenAt` 은 있으나 가입 경로·행동 이벤트 저장소는 없다. 방 수 통계는 봇 방을 제외하지 않고 유저 수만 제외한다.
- 병목 근거: 누적 438계정인데 주간 활성 1명, 10인 방 1건 (메모리 `conversion_baseline_2026_05`). 획득이 아니라 **내전 성사**가 병목이다.
- 스키마 변경은 `migrate deploy` 로 반영한다. dev compose 는 쓰지 않는다. 마이그레이션은 이전 Phase 와 섞지 않는다.

## Phase 1 — 병목을 화면에 올린다

> **정정(구현 중 확인):** 방은 끝나거나 비면 `deleteRoomData` 등으로 DB 에서 **삭제된다**(삭제 경로 3곳).
> 그래서 Room 테이블만으로는 과거 깔때기를 만들 수 없고, 처음 계획의 "지금 데이터로 가능"은 틀렸다.
> 방이 지워질 때 결과 한 줄(`RoomOutcome`)을 남기도록 바꿨고, **배포 이후 쌓이는 방부터** 집계된다.

- [x] Task 1: 봇 제외 기준 통일 — 방·기록·클랜 통계에서 봇 방(호스트가 테스트 봇이거나 참가자 전원이 봇인 방)을 가리는 공용 where 를 만들고 `getStats` 의 모든 지표에 적용
- [x] Task 2: 방 깔때기 — `RoomOutcome` 기록 추가 후 게임별 생성 → 시작 → 결과 건수·비율 (기간 7/30/90일), 대시보드 게임 탭에 단계 막대로 표시. 정원 충족은 "지워질 때" 기준이라 보조 지표
- [x] Task 3: 방 단위 지표 — 대기 시간 중앙값, 시작한 방 평균 인원, 빈 방 종료 비율. **연속 내전 유저 비율은 뺐다**(유저별 참가 이력이 방과 함께 지워져 계산할 근거가 없다. Phase 3 이벤트 로그 몫)
- [x] Task 4: 위 지표의 단위 테스트 — 봇 방 제외, 0건일 때 0 나눗셈 방지, 기간 경계

## 순서와 의존

- Phase 1 은 단독으로 가능하다. 가장 먼저 한다.
- Phase 2 는 Phase 1 의 봇 제외 기준(Task 1)을 스냅샷 집계에도 써야 하므로 Task 1 뒤에 한다. 단, 시작이 늦을수록 손실이 커서 Phase 1 과 병행해도 된다.
- Phase 3 의 Task 10 은 가입이 늘기 전에 넣는다. Task 12 는 문서만이다.
- Phase 4 는 서로 독립이다. Task 15 가 먼저 끝나면 Task 17 이 그 컴포넌트를 쓴다.
- Phase 5 의 Task 19 는 유저 쪽 기능을 더 얹기 전에 한다.

## 결정이 필요한 것

- 활성 유저 정의: `lastSeenAt` 이 그날인 유저 vs 방 참가·입찰 등 의미 있는 행동을 한 유저. 전자는 구현이 쉽고 후자는 병목 분석에 맞다.
- 일별 스냅샷의 게임 구분: 활성 유저는 게임과 무관하다. 게임별 활성은 방 참가 기준으로만 정의할 수 있다.
- 개인정보: 가입 경로의 리퍼러 저장 범위, 내보내기 파일의 식별자 처리.
